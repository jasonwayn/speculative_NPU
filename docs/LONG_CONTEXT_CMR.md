# 긴 컨텍스트에서의 tau 붕괴와 CMR — NPU 재현

> ⚠️ **2026-08-21 정정.** 아래 3절의 "NPU 에서는 CMR 이 순손해" 는 **폐기합니다.**
> 오버헤드는 알고리즘이 아니라 호스트 구현이었고, 세 군데를 고치자 **16384 에서
> stock 대비 1.02(pg19) / 1.09(govreport) 배**가 됐습니다 (기존 0.31 / 0.32).
> 그래프는 안 건드렸고 tau 는 20/20 그대로입니다.
> → [HOST_THREAD_STARVATION.md](HOST_THREAD_STARVATION.md), `results/corpus_v3/`

Date: 2026-08-21

## 요약

**GPU 에서 관찰된 CMR 의 긴 컨텍스트 이득이 NPU 에서 그대로 재현됩니다.**
tau 는 두 하드웨어에서 2~3% 안으로 일치합니다.

~~다만 NPU 에서는 CMR 의 오버헤드가 tau 이득을 압도해 처리량이 3~7배 떨어집니다.~~
**정정**: 그 오버헤드는 전부 호스트 구현이었습니다. 스레드 경합·GQA 물리 복사·키
저장소 재할당 세 가지를 고치자 **16384 에서 1.02 / 1.09 배로 순이득**이 됩니다.
손익분기는 8192 와 16384 사이이고, 남은 비용은 **호스트 스코어러 하나**(10.9~12.5 ms)
입니다. 그것을 그래프로 옮기면 1.30 / 1.40 배로 GPU(1.28 / 1.32) 와 같아집니다.

## 1. 실험 조건

| | |

| 길이 | 1024 / 2048 / 4096 / 8192 / 16384 (실측 995 ~ 16355 토큰) |

> ⚠️ 샘플은 토큰 스트림에서 정확히 N개를 잘라내므로 문장·문단 경계를 무시합니다.

## 4. CMR 구현 메모

**드래프터 캐시만 자릅니다.** 타깃의 `VL` 과 `cache_position` 은 건드리지 않습니다.
타깃을 자르면 투기 디코딩이 무손실이 아니게 되기 때문입니다 — 드래프터를 자르면
tau 만 떨어지고 정확도는 그대로입니다.

**메모리는 안 줄어듭니다.** 캐시 텐서는 `MAXC` 로 정적 할당돼 있고 CMR 은 읽는 길이
(`ctx_len`)만 줄입니다. NPU 에서는 연산량만 아낍니다.

**선택 규칙** (`bench_cmr_parts.pick_chunks`)

```python
means = 청크(32칸)별 평균 어텐션 확률
keep  = topk(means, 32)     # 점수 상위 32청크
keep.add(n - 1)             # 최신 청크 강제
idx   = [keep 의 위치들, 오름차순]
return idx[:budget]         # 1024 로 절단
```

점수는 **로짓이 아니라 softmax 확률**이고, 타깃 레이어 35 의 32개 헤드와 최근 쿼리
M개의 평균입니다. 즉 "타깃이 지금 어디를 보고 있는가"입니다.

> `idx[:budget]` 이 **위치 오름차순 앞에서부터** 자르므로, 초과가 나면 방금 강제로
> 넣은 최신 청크가 잘립니다. 이번 실험에서는 `kept_mean` 이 전 구간 1008 로
> 예산(1024) 아래여서 발생하지 않았습니다. 설정을 바꾸면 걸릴 수 있습니다.

  (`Scorer._rope` 가 `e.cos()`/`e.sin()` 을 그대로 부릅니다. 지금은 호스트라 무해)
